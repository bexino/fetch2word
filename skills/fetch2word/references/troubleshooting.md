# 抓取要点与排错

## 页面字段从哪来

| 字段 | 来源 | 备注 |
|---|---|---|
| 标题 | `<meta property="og:title">` | 兜底 `var msg_title = '...'`，再兜底 `#activity-name` |
| 日期 | `var createTime = 'YYYY-MM-DD HH:MM'` | 兜底 `var ct = "<秒级时间戳>"` |
| 正文 | `#js_content` | 递归 walk，文本块与 `img` 按文档顺序产出 |
| 图片 | `img[data-src]` | 懒加载，`src` 常为空；相对协议补 `https:` |
| 图片格式 | URL 的 `wx_fmt` 参数 | 仅用于存盘后缀，实际格式以文件头为准 |

请求头必须带桌面 UA。单篇 HTML 约 3~4 MB，属于正常（含大量内联样式）。

## 图片下载

- **必须带 Referer**：`https://mp.weixin.qq.com/`，否则部分 CDN 直接拒绝
- **必须重试**：同一 URL 失败两次后换 `/0?`（原图）再试一次
- 失败产物常是 331 字节的小包（错误页），用「体积 < 500 字节」即可识别
- 尾部装饰图（`END` 分隔条）有一定概率永久 404，属正常损耗，报警即可

## 风控与异常页

收到"环境异常""请在微信客户端打开"之类页面时，`#js_content` 不存在，表现为解析为空。处理方式：

1. 稍后重试（并发降到 3~4）
2. 加 Cookie（有登录态时更稳）
3. 仍失败则在该批清单里标注失败，不要编造内容

## 排序

清单文件里若出现 `排序：从旧到新` 或 `排序：从新到旧`，`--sort auto` 会读取并执行；没有提示行则不排序，保持清单原顺序。

## 排错对照

| 现象 | 原因 | 处理 |
|---|---|---|
| `PermissionError` 保存失败 | 文件正在 Word/WPS 中打开 | 提示关闭；或先探活跳过该篇再重跑 |
| 正文出现大片空行 | 未过滤 `<p><br></p>` | 确认 `strip_empty_paragraphs()` 生效 |
| 图片莫名少了 | 被当成低清图标 | 看 `_manifest.csv` 的「跳过明细」；必要时调低 `--min-px` |
| Word 里图片红叉 | 悬空 `r:embed` | 按引用集合反查重删，别按段落逐个 `drop_rel` |
| 文档体积异常大 | 模板 media 未回收 | 检查 `drop_rel` 步骤 |
| 页面变 Letter | `sectPr` 被删 | 恢复 `clear_body()` 的 sectPr 保留逻辑 |
| 整篇解析为空 | 风控/环境异常页 | 重试、降并发、加 Cookie；报告中标注失败 |
| 图片只有 331 字节 | CDN 拒绝该资源 | 正常损耗，跳过并报警 |
| 正文段落被合并 | 误用「相邻段合并」 | 每个 `<p>`/`<section>` 必须独立成段 |
| 标题出现两个栏目名 | 原文自带前缀又补了 `--column` | 只在无 `||` 时才补 |
| 篇数与清单不符 | 清单里有重复链接 | 保持按出现顺序去重逻辑 |

## 环境偏好

- 只用标准库 `urllib` 下载，`curl` 作为兜底。**不要**引入 `requests`——某些机器上它的 `urllib3` 安装残缺（`ModuleNotFoundError: urllib3.util.url`），会连带把整个流程卡死
- python-docx 解析不了的格式（webp 等）用 Pillow 转 jpg 兜底；没装 Pillow 则记为失败并报出
- 批量写文件前统一探活，Windows 上被占用的文件写不进去

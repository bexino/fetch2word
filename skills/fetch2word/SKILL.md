# fetch2word：公众号推文 → 模板化 Word

## 何时使用

- 用户给一批 `mp.weixin.qq.com/s/...` 链接，要求转成 Word
- 要求套用**固定版式**（页边距、字号、标题写法一致）
- 要求图片内嵌，但**不要 gif 装饰、不要低清小图标、不要空行**
- 要求**去掉文末二维码、开头红旗礼花这类装饰素材、以及文末的 END 标记**
- 要求文件名 `yyyy.mm.dd(标题).docx` 并归到产出目录

**不适用**：需要改写正文内容、需要保留音频/视频/投票等互动元素、非公众号站点。

## 版式：内置，无需准备模板

模板随 skill 分发，位于 `assets/template.docx`，脚本默认使用它。**不需要**在项目里放 `模板/` 目录，也不需要传 `--template`。

这份模板已脱敏：机构名统一为「某某职业学院 / 某某学院」，人名统一为「张某某」式，配图为同尺寸占位图；**页面尺寸、页边距、段落格式、字号字重、图片位置与尺寸与原始模板逐项一致**。

只有确实要换版式时才用 `--template <path>` 覆盖——那是例外，不是常规动作。

## 目录约定（禁止写死绝对路径）

| 用途 | 位置 | 说明 |
|---|---|---|
| 链接清单 | `链接/<月份>.txt` | 一行一个 URL，可含「排序：从旧到新」提示行 |
| 产出 | `产物/<月份>/` | 由 `--out` 指定 |

## 输出规格（固定规则；仅「是否简化标题」提供开关）

### 文件名

```
文件名：yyyy.mm.dd(简化标题).docx
```

- `yyyy.mm.dd` 取文章发布日期（`var createTime`），**不是**运行日期
- 括号里是**简化标题**，不是原文标题——原文标题动辄 30 字，文件名没法看
- **默认开启简化**；要原文标题就加 `--no-summarize`（见下）
- 标题中的 Windows 非法字符 `\ / : * ? " < > |` 会被剔除
- 简化标题默认 ≤ 12 字（`--name-max` 可调）
- `check_output.py` 用 `^\d{4}\.\d{2}\.\d{2}\(.+\)\.docx$` 校验格式，
  并检查括号内不超过 16 字（超了说明根本没简化）

示例：

```
情暖重阳，爱满新才！机电与建筑工程学院志愿者赴青山路街道新才社区传递敬老温情
  → 2025.10.11(青山路街道敬老).docx
我为同学办实事|清洗空调滤网，守护夏日“呼吸健康”
  → 2025.10.12(清洗空调滤网).docx
```

### 简化标题怎么来（默认路径）

`title_naming.short_title()` 是纯规则、纯字符串处理：**只看标题这一行字**，
不读正文、不额外抓页面、不调用模型。切片段 → 丢掉口号抒情段 → 剥掉机构名和
「赴/走进」这类引导动作 → 去掉尾巴上的煽情词 → 裁到上限。

规则给的是「还过得去」的底线。AI 觉得某几篇简化得别扭时，用映射表覆写：

```bash
# 1) 只列标题（几秒钟，不重抓、不重排版）
python <skill>/scripts/shorten_titles.py --out "产物/10月" --list

# 2) AI 只读这些标题，写 命名.tsv（每行「原文标题<TAB>简化名」，URL 也行）
# 3) 按映射改名，docx 内容一个字节都不动，清单同步更新
python <skill>/scripts/shorten_titles.py --out "产物/10月" --apply "命名.tsv"
```

也可以在第 1 次生成时直接给 `--names 命名.tsv`，免去二次改名。

映射表优先级高于规则；没命中的篇目维持原样。

### 不要简化：`--no-summarize`

```bash
python <skill>/scripts/wx2docx.py --links "链接/10月.txt" --out "产物/10月" --no-summarize
```

- 文件名回到「原文标题（去栏目前缀）」，最长 60 字截断
- 此时 `--name-max` 与 `--names` 映射表都忽略（简化整个关掉）
- 自检要同步关掉长度项：`check_output.py --out "产物/10月" --name-max 0`
  （否则会被判「标题未简化」）

### 日期行

```
yyyy.mm.dd（发出日期）
```

**（发出日期）四个字是硬约束**：写在 `DATE_NOTE` 常量里，既不读参数、也没有开关，`--date-note` 参数已移除。`check_output.py` 用
`^\d{4}\.\d{2}\.\d{2}（发出日期）$` 逐字校验，缺一个字即判不合规。

这样无论在哪台机器、哪个目录、谁来跑，生成结果的日期行都一致。

## 快速开始

```bash
python -m pip install python-docx beautifulsoup4 lxml pillow

python <skill>/scripts/wx2docx.py \
  --links "链接/10月.txt" \
  --out "产物/10月"
```

| 参数 | 默认 | 作用 |
|---|---|---|
| `--column` | `学院动态` | 标题无栏目前缀时补的前缀；`""` 不补 |
| `--sort` | `auto` | 读清单里的排序提示；可 `asc`/`desc`/`none` |
| `--names` | 无 | 简化标题映射表（两列，Tab/逗号分隔），优先级高于内置规则 |
| `--no-summarize` | 关 | **关掉文件名标题简化**，直接用原文标题 |
| `--name-max` | 12 | 简化标题的字数上限；`--no-summarize` 时不生效 |
| `--keep-gif` | 关 | 保留 gif |
| `--no-heading` | 关 | 关闭小标题识别，全部按正文输出 |
| `--min-px` | 200 | 最长边低于此值视为装饰图标 |
| `--min-area` | 40000 | 像素面积低于此值视为低清装饰图 |
| `--alpha-frac` | 0.10 | 透明像素占比超过此值即判为装饰贴图，**全文生效**；别往下调太低，会误删带透明边的拼图 |
| `--workers` | 8 | 并发数 |
| `--cache` | 系统临时目录 | 保留中间产物便于复跑排错 |
| `--template` | 内置 | 仅特殊情况下覆盖版式 |

产出：docx + `_manifest.csv`（文件名 / 日期 / 标题 / 简化标题 / 内嵌图数 / 跳过数 / 跳过明细 / 原文链接）。

## 硬规则（按优先级）

1. **版式跟随内置模板**：页边距、字号、加粗、图片版心宽度由 `read_template_spec()` 从模板读出，代码里不写死数值。
2. **清空正文必须保留 `w:sectPr`**，否则页面尺寸退回 Letter。
3. **删图只能按「XML 实际引用的 rId 集合」反查回收**，绝不按段落逐个 `drop_rel`——同一张图可能复用同一 rId，逐个删会留下悬空引用（Word 里是红叉）。
4. **日期行固定为 `yyyy.mm.dd（发出日期）`**，硬编码在 `DATE_NOTE`，不提供任何参数或开关，且必须被自检逐字校验。
5. **删除所有完全空的段落**（无文字、无图片）。
6. **gif 一律当装饰删除**，按文件头 `GIF8` 判定，别只信后缀。
7. **低清图当装饰删除**：最长边 < `--min-px` 或面积 < `--min-area`。
8. **图片下载要重试 + 原图回退**：`/640?` 被拒换 `/0?` 再试，最多 3 次。
9. **丢图必须报警**，终端与清单都要列出，不许静默跳过。
10. **文件名里的标题必须是简化标题**：默认走 `title_naming.short_title()` 规则简化，
    格式 `yyyy.mm.dd(简化标题).docx`；需要原文标题时显式加 `--no-summarize`，
    不许默默拿 40 字长标题当文件名。简化只允许看标题字符串，**不许为了起名字去读正文或重抓页面**。
    栏目前缀仍统一用 `||` 分隔（`学院动态||xxx`），文件名只取 `||` 之后的标题部分。
11. **正文段落一律首行缩进 2 字符**。用 `w:ind@firstLineChars="200"` 为主（Word 按“字符”算），同时写 `w:firstLine` 作 twips 兜底，保证 Word/WPS/LibreOffice 一致。**小标题、日期行、标题行、图片段落都不缩进**。
12. **序号块要和标题合并成一行**。公众号常把「05」和「选拔原则」拆成两段，落到 Word 会断成两行。识别到纯序号块（`05`/`5`/`一、`/`（二）`/`附件1`）紧跟短标题时，合并为「05 选拔原则」，并沿用标题样式（小标题，不是正文）。
13. **小标题要保留层级，不要拍平**。公众号小标题多为 `<section>` 内近乎全文加粗、短句、居中（如「活动第一项：升国旗，奏国歌」）。判定条件：长度 ≤40 字、句末不带 `。！？`、加粗覆盖率 ≥85%。命中后一律**居左**：加粗 + 正文字号 +1 为一级，加粗 + 正文字号 +0 为二级；一级另加段前后 6pt。**不要居中**，居中会破坏模板整体观感。误判时用 `--no-heading` 全部按正文输出。
14. **文末 END 标记必须删掉**。不只 `END` 三个字母——`-END-`、`——END——`、`（完）`、`THE END`、`全文完`、`END.` 都算。判据写在 `filters.is_end_marker()`：先剥掉空白与中英文标点，再比核心词。**只在文末生效**：END 之后若还有正文，说明它不是结束标记，原样保留（宁可不删也不误删正文）。END 之后仅剩图片/二维码时，一并清掉。
15. **二维码必须删掉，且不能靠尺寸判**。公众号文末二维码常见 258×258、260×260，既过得了 `--min-px 200`，面积也远超 `--min-area 40000`，按尺寸永远删不掉。改用结构判据（`filters.is_qr_code()`）：**近正方形（长宽比 0.80~1.25）+ 黑白二值化纯度高（近黑近白占比 ≥85%）+ 横向跳变密集（≥6%）**，三条同时满足才判定。中心压了 logo 的二维码照样命中；实拍照片、横幅、表格图都过不了这三条。
16. **透明底装饰素材要全文删，不只看开头**：正文中间夹的艺术字、枫叶、分割条贴纸才是真实生产里最容易漏的那批（实测「燃动英雄马」正文中段一张 84% 透明的 Youth 艺术字、「燃动赛场」一张 55% 透明的枫叶，都因为只查开头而漏进 Word）。判据 `filters.has_transparency()`：透明像素占比 **> `--alpha-frac`（默认 10%）**。
    - **阈值不能低**：实测 21 篇产出里 17 张透明 PNG，真照片存成 PNG 时四角透明边最高 **2.1%**，装饰贴纸是 **55%~92%**，中间是空档。定 2% 会把带透明边的拼图、圆角长图当装饰删掉；定 10% 两头都安全。
    - **转格式不能丢 alpha**：`ensure_supported()` 把 webp 转 PNG（不是 JPEG），否则透明通道被压成白底，贴纸就此洗白成普通图片、后面永远认不出来。
    - **整篇图片都是透明底**（设计稿式长图推送）时不套用，否则产出是空壳。
17. **开头超宽横幅**（不透明、长宽比 ≥2.2）仍单独判，且只在正文第一段文字之前生效。
18. **链接按出现顺序去重**。
19. **写入前探测占用**（`open(f,"r+b")`），被 Word/WPS 占用的跳过提示；`~$` 是锁文件，别删。

## 交付前自检

```bash
python <skill>/scripts/check_output.py --out "产物/10月"
```

要求全绿：`gif=0`、`empty=0`、`dangling=0`、`qr=0`、`low-res=0`、`透明素材=0`、无开头横幅、无文末 END、文件名合规则且标题已简化（括号内 ≤16 字，`--name-max 0` 可关）、首段严格为 `yyyy.mm.dd（发出日期）`、第 3 段起无居中段落、正文段落都有首行缩进。
任何一项不绿就不算完成。

生成端与自检端**共用 `filters.py` 里的同一套判据**，不许两边各写一份——否则删了看不出来，或者看不出来还误报。

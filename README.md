# fetch2word

把**微信公众号推文批量转成统一版式的 Word 文档**。

给它一份链接清单，它抓取正文、下载图片、套用内置模板排版，输出 `yyyy.mm.dd(简化标题).docx`。装饰性 gif、低清小图标、文末二维码、开头礼花横幅、空行全部清理干净，文末 `END` 一并屏蔽，图片内嵌不留外链。

模板已内置，开箱即用。文件名里的标题默认**自动简化**（原文标题动辄 30 字，塞进文件名只能靠运气认）：

```
情暖重阳，爱满新才！机电与建筑工程学院志愿者赴青山路街道新才社区传递敬老温情
  → 2025.10.11(青山路街道敬老).docx
我为同学办实事|清洗空调滤网，守护夏日“呼吸健康”
  → 2025.10.12(清洗空调滤网).docx
```

不想要简化就加 `--no-summarize`。

## 特性

- **开箱即用**：模板随仓库分发（已脱敏），只需提供链接清单
- **版式稳定**：页边距、字号、加粗、图片版心宽度全部从模板读取，代码不写死数值
- **小标题还原**：自动识别原文的加粗/居中短句，转为一/二级小标题，不再全篇一个样
- **正文规范**：正文段落首行缩进 2 字符；「05 + 标题」这类拆分序号自动合并成一行小标题
- **图片内嵌**：按原顺序插入，带重试与原图回退，丢图会报警
- **二维码识别**：文末「扫码关注」那张二维码按**结构**判（近正方 + 黑白纯度高 + 跳变密集），不靠尺寸——258×258 的小图按尺寸永远删不掉，中心压了 logo 的照样认得出来
- **开头装饰素材**：正文第一段之前的透明底贴图（红旗、红绸、华表、礼花）与超宽横幅直接丢弃，实拍照片照常保留
- **文末 END 屏蔽**：`END`、`-END-`、`（完）`、`THE END`、`全文完` 一律删除；仅当它确实在文末才删，正文里的 END 字样不误伤
- **干净输出**：剔除 gif 装饰、低清图标、空段落；回收模板残留部件，体积通常减少 60% 以上
- **文件名可读**：默认把长标题简化成 ≤12 字要点，只读标题、不读正文；`--no-summarize` 可退回原文标题
- **可移植**：零绝对路径，换机器只要保持目录结构
- **可核查**：产出附带 `_manifest.csv`，另有自检脚本一键验证合规性

## 安装

```bash
git clone <your-repo-url> fetch2word
```

把 `skills/fetch2word/` 整个目录复制到你的 Skill 目录：

| 作用域 | 目标路径 |
|---|---|
| 项目级 | `<项目>/.workbuddy/skills/fetch2word/` |
| 用户级（全局） | `~/.workbuddy/skills/fetch2word/` |

安装依赖：

```bash
python -m pip install python-docx beautifulsoup4 lxml pillow
```

## 使用

项目里只需要一个链接清单：

```
你的项目/
├── 链接/10月.txt          # 一行一个 mp.weixin.qq.com 链接，可含「排序：从旧到新」
└── 产物/10月/              # 输出
```

```bash
python .workbuddy/skills/fetch2word/scripts/wx2docx.py \
  --links "链接/10月.txt" \
  --out "产物/10月"
```

跑完自检：

```bash
python .workbuddy/skills/fetch2word/scripts/check_output.py --out "产物/10月"
```

要求 `gif=0`、`empty=0`、`dangling=0`、`qr=0`、`low-res=0`、无开头装饰素材、无文末 END、文件名合规、日期行为 `yyyy.mm.dd（发出日期）`、无居中段落、正文均有首行缩进；退出码非 0 说明有问题。

### 常用参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--column` | `学院动态` | 标题无栏目前缀时补的前缀，`""` 不补 |
| `--sort` | `auto` | 读清单里的排序提示；也可 `asc`/`desc`/`none` |
| `--keep-gif` | 关 | 保留 gif |
| `--no-heading` | 关 | 关闭小标题识别，全部按正文输出 |
| `--min-px` | 200 | 最长边低于此值视为装饰图标 |
| `--min-area` | 40000 | 像素面积低于此值视为低清装饰图 |
| `--workers` | 8 | 并发数 |
| `--no-summarize` | 关 | **关闭文件名标题简化**，直接用原文标题 |
| `--name-max` | 12 | 简化标题字数上限（`--no-summarize` 时不生效） |
| `--names` | 无 | 简化标题映射表，AI 可覆写个别篇目的简化结果 |
| `--cache` | 系统临时目录 | 保留中间产物，便于复跑排错 |
| `--template` | 内置 | 特殊情况覆盖版式 |

## 小标题

公众号的小标题通常藏在 `<section>` 里——短句、近乎全文加粗、居中，例如「活动第一项：升国旗，奏国歌」。程序按三个条件判定：

1. 长度 ≤ 40 字
2. 句末不带 `。！？`
3. 加粗覆盖率 ≥ 85%（或显式 `font-weight:bold`）

命中后：

| 类型 | 判定 | 呈现 |
|---|---|---|
| 一级小标题 | 加粗 + 居中 | 居左、加粗、正文 +1 号字、段前后 6pt |
| 二级小标题 | 加粗不居中 | 居左、加粗、正文字号 |

小标题一律居左，不跟随原文的居中。

误判时加 `--no-heading`，全部按正文段落输出。

### 序号块合并

公众号 Editor 常把编号和标题拆成两段：`05` 一段、`选拔原则` 一段。程序识别到**纯序号块**（`05`、`5`、`一、`、`（二）`、`附件1`）紧跟短标题时，合并成一行：

```
05 选拔原则
```

合并结果按**小标题**渲染（加粗 + 分级字号），不是正文，也不加首行缩进。

### 正文首行缩进

所有正文段落首行缩进 2 字符，写 `w:ind@firstLineChars="200"` 并带 `w:firstLine` 兜底；小标题、日期行、标题行、图片段落均不缩进。

## 图片与文末过滤（通用限制）

判据集中在 `scripts/filters.py`，生成端与自检端共用同一份，不各写一套。

| 拦截对象 | 判据 | 生效范围 |
|---|---|---|
| 低清装饰图 | 最长边 < 200px 或面积 < 40000px² | 全篇 |
| gif 动图 | 文件头 `GIF8` | 全篇（`--keep-gif` 可留） |
| **二维码** | 长宽比 0.80~1.25 **且** 近黑/近白像素合计 ≥85% **且** 横向跳变 ≥6% | 全篇 |
| **开头装饰素材** | 带透明通道且透明像素 >2%，或长宽比 ≥2.2 的横条 | **仅正文第一段文字之前** |
| **文末 END** | 剥掉空白与标点后核心词命中 `END`/`THEEND`/`本文完`/`全文完`/`完` | **仅文末**（其后还有正文则不动） |

几条设计取舍：

- 二维码不能按尺寸判。公众号文末二维码实测 260×258，既过得了 `--min-px 200`，面积也远超 `--min-area 40000`；只能看结构。三条判据缺一不可——只判正方形会误伤海报竖图，只判黑白纯度会误伤白底表格图。
- 装饰素材只在**开头位置**判。正文中间的大图可能是实拍照片，透明小图可能是排版图标，一律不动；开头那几张红旗/红绸/华表/礼花则必删。
- END 只在**文末**判。正文里偶尔出现 `END` 字样的段落照常保留。
- 整篇都是开头贴图（纯图推送）时不套用开头规则，否则产出是个空壳。

## 输出规格（固定）

### 文件名

```
文件名：yyyy.mm.dd(简化标题).docx
```

| 部分 | 取值 |
|---|---|
| `yyyy.mm.dd` | 文章发布日期，取自页面 `createTime`，不是运行日期 |
| `简化标题` | 从标题文字本身提取的要点，去掉栏目前缀（`公示||xxx` → `xxx`），半角括号包裹 |

**默认简化**：`title_naming.short_title()` 按标点切片段、丢口号抒情段、剥机构名与「赴/走进」这类引导动作、去尾部煽情词，最后裁到 12 字（`--name-max` 可调）。全程只处理标题字符串——不读正文、不额外抓页面、不调模型。

规则失手的篇目可以人工/AI 覆写，不用重抓重排：

```bash
python .workbuddy/skills/fetch2word/scripts/shorten_titles.py --out "产物/10月" --list   # 只列标题
python .workbuddy/skills/fetch2word/scripts/shorten_titles.py --out "产物/10月" --apply "命名.tsv"
```

`命名.tsv` 每行两列（Tab 或逗号）：`原文标题<TAB>简化名`，第一列写 URL 也认。

**不要简化**：加 `--no-summarize`，文件名回到「原文标题（去栏目前缀）」，最长 60 字截断；自检同步加 `--name-max 0`，否则会被判「标题未简化」。

标题中的 `\ / : * ? " < > |` 一律剔除；`check_output.py` 按 `^\d{4}\.\d{2}\.\d{2}\(.+\)\.docx$` 校验格式，并检查括号内不超过 16 字。

### 日期行

```
yyyy.mm.dd（发出日期）
```

**（发出日期）是硬约束**：写死在 `DATE_NOTE` 常量，无参数、无开关，自检按 `^\d{4}\.\d{2}\.\d{2}（发出日期）$` 逐字校验，缺字即判不合规。

## 关于内置模板

`skills/fetch2word/assets/template.docx` 是脱敏版模板：

| 项目 | 处理方式 |
|---|---|
| 机构名 | 「某职业学院 / 某某学院」等泛化名称 |
| 人名 | 统一替换为「张某某」「李某某」式 |
| 地点 | 「某报告厅」等泛化表述 |
| 配图 | 替换为同尺寸灰阶占位图（10 张，像素尺寸与原件逐一对应） |

**版式零改动**：页面尺寸、页边距、段落数（27）、段落格式、字号字重、图片位置与显示尺寸，逐项与原始模板比对一致。改动前后的差异仅限文字内容与图片像素。

需要换成别的版式时，用 `--template <path>` 指向自己的 docx。

## 工作原理

1. 读清单、按出现顺序去重，识别排序提示
2. 并发抓页面（`urllib` 优先，`curl` 兜底）
3. 解析 `og:title`、`var createTime`、`#js_content`
4. 并发下载图片（带 Referer，失败重试并回退原图）
5. 简化标题（`short_title`，只看标题字符串）→ 定文件名
6. 以模板为基底重建正文，逐段插入文字与图片；每张图先过 `filters.py` 的判据（gif / 低清 / 二维码 / 开头装饰素材），文字段落过文末 END 过滤
7. 回收孤儿部件、删空段，写 `_manifest.csv`

## 已知限制

- 只支持公众号图文页；音频、视频、投票等互动组件不会转换
- 尾部装饰图偶有永久失效，会在报告中标出，需人工决定是否忽略
- 依赖 Word 文档结构（OOXML），不处理 `.doc`、`.wps`
